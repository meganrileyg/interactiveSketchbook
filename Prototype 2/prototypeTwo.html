This week, I refined my prototype by adding to my micro-project layout, and added a home page and sketch example wireframe. The micro-project wireframe has a few further adjustments. These include the title of the interaction being moved to the top of the page for hierarchy (last week it was at the bottom of the page,) an addition of a subheader under the title of the interaction, and more distinct instructions clearly visible underneath it. The page header was made smaller to open up space for the interaction. The drop down menu was kept from the previous wireframe, but I added navigation keys underneath the interaction instructions so that the user can click through sketches chronologically if they want to peruse instead of having to use the drop down menu.

The home page is laid out by section, so that all sketches and projects are visible. Each section will be collapsable for ease of navigation.

The example wireframe for a sketch layout is similar to but simpler than the micro-project layout. The header is at top, with the name of the sketch below the navigation menu, though there is no subheading. The interaction, instructions, and navigation arrows are in the same place. This addresses the audit problem of difficult navigation, as the arrows add an easy click-through option. The menu is always visible to allow the user to navigate by sketch.

Additionally, the instructions being listed below the interaction but always visible make it so that the user does not have to search for what to do. Despite the navigation arrows allowing the user to go forward and back through the sketches, there may be unresolved issues in ease of backtracking. There may be an opportunity for a quicker “back” button.
